# ADR-0002: 文档与 ADR 驱动的 AI 开发流程

- **状态：** Accepted
- **日期：** 2026-10-17
- **关联：** ADR-0001、docs/roadmap.md、.cursor/rules

## 背景

需要可追溯的决策留底，并让 AI 辅助开发时不偏离产品边界与技术基线。

## 决策

1. **单一真相源：**  
   - 产品范围与待决策 → `docs/product/`  
   - 技术基线 → `docs/技术栈.md`  
   - 开发顺序 → `docs/roadmap.md`  
   - 架构/规则决策 → `docs/adr/`  
2. **ADR 粒度：** 每个跨模块或难回滚的决策一篇（状态机、权限、报名一致性、支付等）。页面级文案微调不需要 ADR。  
3. **开发顺序：** `Accepted ADR` → 改代码 → 对照验收 → ADR 标 `Implemented`。  
4. **AI 约束：** Cursor always-apply rule 要求先读 docs/ADR；禁止在未更新文档时引入支付、uni-app x、Vue2、云开发主后端。  
5. **阶段交付：** roadmap 每阶段是可演示垂直切片，不是「先做完前端再后端」。

## 备选方案

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 只写 PRD、口头决策 | 快 | 无法留底，AI 易跑偏 |
| 每文件都写 ADR | 极细 | 噪音大，维护成本高 |

## 后果

- 正面：决策可审计；AI 与人类同一套约束。  
- 负面：小改也要先判断是否需要 ADR（用模板快速写）。  
- 跟进：后续阶段 ADR-0003～0009 按 roadmap 推进时填写。

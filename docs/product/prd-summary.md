# 产品需求摘要（来自 PRD V1.0）

原文：`docs/产品文档.docx`（活动报名类微信小程序 PRD 模板）。

## 一句话定位

面向公众的活动发现与报名小程序：组织者发布活动，用户浏览并报名，平台后台审核与治理。

## 角色

| 角色 | 核心能力 |
| --- | --- |
| 访客/用户 | 浏览、报名、我的报名 |
| 组织者 | 创建/管理活动、查看报名名单 |
| 平台运营/管理员 | 审核、下架、组织者权限、基础 RBAC |

## 首期必须交付（P0）

- 活动创建/编辑/草稿/发布（含审核）  
- 活动列表与详情  
- **免费**报名闭环（幂等、名额、防重复）  
- 我的报名 + 组织者报名名单  
- 后台审核/下架 + 基础权限  

## 首期不做

在线支付/退款、扫码签到、评价、候补、优惠券/分销、复杂推荐、多场次系列活动。

## 已锁定的产品默认

见设计规格与 ADR-0001 关联结论；明细表：

| ID | 默认 |
| --- | --- |
| D-01 | 申请成为组织者后可发布 |
| D-02 | 新组织者活动必审 |
| D-03 | 报名默认直接成功 |
| D-04 | 名额按有效报名记录数 |
| D-05 | 不做在线支付（预留费用字段） |
| D-06 | 取消报名 → P1 |
| D-07 | 独立 Web 管理后台 |
| D-08 | 表单：姓名 + 手机号 |
| D-09 | 线上活动首期可不做 |
| D-10 | 联系方式避免裸露隐私 |

## 核心状态（逻辑）

- 活动审核：`not_required | pending | approved | rejected`  
- 活动生命周期：`draft | published | cancelled | removed | ended`（展示态可由时间/名额计算）  
- 报名：`confirmed`（首期）；`pending_review` 等预留  

## 关键非功能

- 服务端判定名额与权限，不信任前端  
- 报名接口幂等；并发不超卖  
- 敏感操作审计  

## 验收锚点

PRD 第十章：`AT-ACT-*`、`AT-REG-*`、`AT-ADM-*`。开发以这些用例为阶段完成标准。

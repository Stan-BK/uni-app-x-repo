# 技术栈说明

> 本文档是本项目的技术选型与工程约束基线。后续开发（含 AI 辅助）应以本文为准；若需变更，先改本文再改代码。

**文档版本：** 2026-10-16  
**适用阶段：** 项目初始化 / 脚手架搭建 / 日常功能开发

---

## 1. 结论（先读）

| 决策项 | 选择 |
| --- | --- |
| 框架 | **传统 uni-app（Vue3）**，不使用 uni-app x |
| 构建 | **Vite** |
| 状态管理 | **Pinia** |
| 语言 | 优先 **TypeScript**（可先 JS 脚手架，尽快切 TS） |
| 样式预处理 | **dart-sass / SCSS**（禁用 node-sass） |
| 主目标端 | **微信小程序** |
| 扩展目标端 | **抖音小程序**、**小红书小程序** |
| 暂不纳入 | App（Android / iOS / 鸿蒙）、uni-app x、Vue2 |

**一句话：** 用官方 Vue3 + Vite 正式版做多端小程序；业务页面尽量复用，登录 / 支付 / 分享等能力按平台拆分。

---

## 2. 为什么不用 uni-app x

官方（截至 2026-10）明确：uni-app x 小程序端目前仅支持 **微信** 与 **支付宝**；抖音在路线图中、尚未落地；小红书不在已支持列表。

本项目需要覆盖微信、抖音、小红书，因此：

- **不能**以 uni-app x 作为当前主技术栈；
- 传统 uni-app 官方平台标识已覆盖：`mp-weixin`、`mp-toutiao`、`mp-xhs`；
- 官方表述：只做小程序时，uni-app 与 uni-app x 均可，x 略有优势——但该优势仅对已支持平台成立。

关于停维：官方将于 **2027 年初**停止传统 uni-app 的 **App 端** 与 uni-app x **VDOM 模式**维护；**小程序端未宣布停维**。「停止维护」不等于下线，无重大问题可不更新。本项目当前只做小程序，与该路线不冲突。若未来做 App，再评估迁移至 uni-app x 蒸汽模式。

## 3. 推荐版本基线

以官方模板 `dcloudio/uni-preset-vue#vite` / `#vite-ts` 对齐最新**正式版**。文档整理时模板依赖约为：

| 组件 | 版本 / 要求 |
| --- | --- |
| `@dcloudio/uni-*` 编译器族 | `3.0.0-5020620260917001`（对应发布线约 **5.26.20260918**） |
| Vue | `^3.4.21` |
| Vite | `5.2.8`（跟随官方模板锁定） |
| Node.js | **18+ / 20+**，优先 **Node 20 LTS** |
| Pinia | 2.x（Vue3 项目内置支持；文档记载内置参考版本约 2.1.7） |
| `@dcloudio/types` | 与编译器同步安装 |

### 创建项目

```bash
# TypeScript（推荐）
npx degit dcloudio/uni-preset-vue#vite-ts <project-name>

# 或 JavaScript
npx degit dcloudio/uni-preset-vue#vite <project-name>

cd <project-name>
npm install
npm run dev:mp-weixin
```

### 升级编译器

CLI 项目编译器在项目内，**不会**随 HBuilderX 自动升级：

```bash
npx @dcloudio/uvm@latest
```

升级后需回归：微信、抖音、小红书三端编译与核心流程。

### HBuilderX 与 CLI

| 方式 | 说明 |
| --- | --- |
| CLI（推荐本仓库） | 编译器在 `node_modules`，适合 Git / CI / Cursor 等 IDE |
| HBuilderX 可视化 | 编译器在 IDE 插件目录，随 HBuilderX 升级 |

可将整个 CLI 工程拖入 HBuilderX 使用；拖入**整个项目**时走项目内编译器，仅拖入 `src` 则走 HBuilderX 内置编译器——本项目统一走 **项目内 CLI 编译器**。

## 4. 工程配置约定

### 4.1 目录与脚本

预期脚本（以官方模板为准）：

```bash
npm run dev:mp-weixin      # 微信开发
npm run build:mp-weixin    # 微信发行
npm run dev:mp-toutiao     # 抖音开发
npm run build:mp-toutiao
npm run dev:mp-xhs         # 小红书开发
npm run build:mp-xhs
```

产物目录：

- 开发：`dist/dev/<platform>`
- 发行：`dist/build/<platform>`

用各端开发者工具打开对应目录预览 / 上传。

### 4.2 manifest / pages

- `manifest.json`：Vue 版本固定为 **Vue3**。
- `pages.json`：主包只放启动必需页；业务页尽早 **分包**；微信 Vue3 可使用 **独立分包**（编译器 5.26+）。
- 条件编译平台标识：

| 宏 | 平台 |
| --- | --- |
| `MP-WEIXIN` | 微信小程序 |
| `MP-TOUTIAO` | 抖音小程序 |
| `MP-XHS` | 小红书小程序 |
| `MP` | 以上小程序合集（慎用，易掩盖端差异） |

### 4.3 Vite

```js
import { defineConfig } from 'vite'
import uni from '@dcloudio/vite-plugin-uni'

export default defineConfig({
  plugins: [uni()],
  // 小程序源码调试需要时再开启
  // build: { sourcemap: true },
})
```

### 4.4 环境变量

- Vue3 / Vite：使用 **`VITE_` 前缀**（如 `VITE_API_BASE`）。
- 禁止沿用 Vue2 的 `VUE_APP_*`。
- 非 H5 端按官方说明使用 `process.env.*` / `import.meta.env` 约定，勿假设 Node 完整 `process` 对象可用。

### 4.5 状态管理（Pinia）

在 `main` 中创建并挂载 Pinia；**小程序端必须从 `createApp` 返回 `Pinia`**（官方要求）：

```js
import { createSSRApp } from 'vue'
import * as Pinia from 'pinia'
import App from './App'

export function createApp() {
  const app = createSSRApp(App)
  app.use(Pinia.createPinia())
  return { app, Pinia }
}
```

禁止新项目使用 Vuex 作为默认方案（遗留迁移除外）。

### 4.6 TypeScript

- `script` 使用 `lang="ts"` 时，该文件导入的组件也应可被 TS 正确解析。
- `tsconfig.json` 的 `compilerOptions.types` 至少包含 `@dcloudio/types`。
- 微信可按需补充 `miniprogram-api-typings`。

### 4.7 UI 与依赖

- 优先：**uni-ui**，或明确支持 Vue3 的组件库（如 wot-ui、uv-ui 等）。
- **禁止**默认引入仅支持 Vue2 的旧库（如早期 uView 1.x）。
- npm 包须适配小程序环境；依赖 `window` / `document` 的浏览器库默认不可用。
- 插件市场组件上线前，至少在 **微信** 验证；抖音 / 小红书单独验收。

## 5. 多端开发原则

### 5.1 分层

```text
共用层：页面结构、业务组件、请求封装、工具函数、Pinia store
分端层：登录、支付、分享、订阅消息、交易组件、开放能力 API
```

- 页面与 UI 尽量共用；
- 平台能力通过适配层（如 `adapters/auth.ts`、`adapters/pay.ts`）隔离，内部用条件编译或策略映射；
- 避免在业务页面散落大量 `#ifdef`，优先收口到适配模块。

### 5.2 已知平台差异（必须按端处理）

| 能力 | 说明 |
| --- | --- |
| 登录 / 用户信息 | 三家授权与会话体系不同 |
| 支付 / 交易 | 接口与组件差异大；小红书能力面通常窄于微信 |
| 分享 | 卡片字段、可分享范围不同 |
| 包体积 | 微信主包限制严格（常见 2MB 主包约束），需分包治理 |
| 小红书工具链 | 官方文档要求对 `@dcloudio/uni-mp-xhs`、相关 vue 运行时做 patch；HBuilderX 往往不能一键打开小红书 IDE，需 CLI 编译后手动导入 `dist` |

小红书相关 patch **必须提交进仓库**（如 `patch-package` / pnpm patch），保证 CI 与本地一致。

### 5.3 性能约定

- 控制 `setData` 等价更新量：列表分页、避免一次性超大响应式对象。
- 长列表使用各端可行的虚拟列表 / 分页方案，并在目标端实测。
- 图片：合适尺寸、懒加载、避免主包塞入大图。

## 6. 相对旧技术栈的升级点

| 维度 | 旧常见做法 | 本项目 | 收益 |
| --- | --- | --- | --- |
| Vue | Vue2 | Vue3 | Composition API、更好的 TS、Pinia；Vue2 已停维新能力 |
| 构建 | webpack | Vite | 冷启动与 HMR 更快 |
| 状态 | Vuex | Pinia | API 更简单，类型友好 |
| Sass | node-sass | dart-sass | node-sass 已停维 |
| 环境变量 | `VUE_APP_*` | `VITE_*` | 对齐 Vite |
| 入口 | `new Vue()` | `createSSRApp` + `createApp()` | Vue3 标准写法 |
| 小程序 | 常规分包为主 | 支持独立分包等（微信 Vue3，视编译器版本） | 启动与包体优化空间更大 |

**新项目禁止选用 Vue2「求稳」。** Vue2 / plus / nvue 官方已停维新功能；微信开发者工具与新 API 适配以 Vue3 为主线。

## 7. AI 文档驱动开发约定

后续用 AI 开发时，默认遵守：

1. **先读本文与 `docs/` 下相关文档**，再改代码；冲突以本文「结论」为准。
2. **不引入 uni-app x、Vue2、webpack 脚手架**，除非文档先修订选型。
3. 新增依赖前确认：Vue3 兼容、小程序可运行、三端或至少微信可验证。
4. 涉及登录 / 支付 / 分享 / 订阅消息：默认走适配层，禁止只写微信 API 就当全端完成。
5. 条件编译优先放在适配层；页面内 `#ifdef` 保持少而清晰。
6. 改动编译器大版本后：列出回归清单（微信编译、抖音编译、小红书编译、登录、支付冒烟）。
7. 不把「浏览器能跑」当成「小程序能跑」；不把「微信能跑」当成「抖音 / 小红书能跑」。
